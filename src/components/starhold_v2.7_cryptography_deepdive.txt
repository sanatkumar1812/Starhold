STARHOLD V2.7: CRYPTOGRAPHY DEEP DIVE

This document provides a comprehensive breakdown of the cryptographic primitives used in the STARHOLD protocol, explaining their theoretical basis, their specific implementation in this system, and the rationale behind their selection.

================================================================================
1. HKDF (HMAC-based Key Derivation Function)
================================================================================

A. GENERAL MECHANISM:
HKDF is a robust key derivation function based on HMAC (Hash-based Message Authentication Code). It follows an "Extract-and-Expand" paradigm. 
- Extract: It takes a source of initial keying material (IKM), which may not be uniformly distributed, and "extracts" a fixed-length pseudorandom key (PRK) using a salt.
- Expand: It "expands" that PRK into one or more cryptographically strong output keys, often using "info" strings to bind the output to specific contexts.

B. SYSTEM IMPLEMENTATION:
In STARHOLD V2.7, HKDF is the heart of the "Tri-Bind" key synthesis.
- Initial Keying Material: The concatenation of the Stellar Geometry Seed and the MASTER_SECRET.
- Salt: The 'Temporal Context' (target_time_utc formatted as YYYY-MM-DD-HH-MM).
- Info: The 'Hardware Identity' (HARDWARE_ID).
- Algorithm: SHA-256.

C. RATIONALE:
We use HKDF instead of simple hashing because it provides cryptographically superior key separation. By using the 'info' parameter for the HARDWARE_ID, we ensure that the same star field produces different keys for different satellites. Using 'salt' for time ensures that keys are rotated every minute even if the stars remain stationary in the field of view.

================================================================================
2. AES-GCM (Authenticated Encryption with Associated Data)
================================================================================

A. GENERAL MECHANISM:
AES-GCM (Galois/Counter Mode) is an "Authenticated Encryption" algorithm. It combines the AES block cipher (in CTR mode) with a Galois field multiplier for authentication.
- Encryption: It turns plaintext into ciphertext.
- Authentication: It generates a 16-byte "Tag" that covers both the ciphertext and any Additional Authenticated Data (AAD).
- Tag Validation: Upon decryption, if the computed tag doesn't match the provided tag, the system knows the data was tampered with or the key is wrong.

B. SYSTEM IMPLEMENTATION:
AES-GCM is used to seal the command packets transmitted from Ground Station to Satellite.
- Key: Produced by the HKDF function.
- Nonce (IV): A 12-byte cryptographically random value generated per-packet.
- AAD: A fixed origin string (b"GS_ALPHA_UPLINK") that identifies the Ground Station.
- Decryption: Wrapped in a try/except block to catch 'InvalidTag' exceptions.

C. RATIONALE:
In a "Zero-Trust" satellite environment, confidentiality is not enough. We must ensure the packet came from our Ground Station and hasn't been modified in transit. AES-GCM provides this integrity (tamper-proofing) out of the box. If a single bit of the command is changed, the authentication fails, protecting the satellite from "bit-flipping" or "replay" attacks.

================================================================================
3. SHA-256 (Secure Hash Algorithm 256-bit)
================================================================================

A. GENERAL MECHANISM:
SHA-256 is a cryptographic hash function that takes an input of any size and produces a fixed 256-bit (32-byte) "digital fingerprint." It is designed to be collision-resistant and irreversible.

B. SYSTEM IMPLEMENTATION:
In STARHOLD, SHA-256 is used in two places:
- HKDF Underlying Primitives: As the hashing algorithm for the HMAC operations inside the key derivation.
- Transparency Reporting: To generate the "Key DNA" (a 12-character hex preview) displayed on the GS and Flight Software dashboards.

C. RATIONALE:
SHA-256 is the industry standard for integrity and fingerprinting. It allows us to give the user "transparency" (showing them a DNA string to verify synchronization) without actually revealing the functional decryption key over the terminal interface.

================================================================================
4. STELLAR GEOMETRY & FUZZY BINNING (The Entropy Source)
================================================================================

A. GENERAL MECHANISM:
Stellar geometry involves calculating the relative angular distances between star centroids (RA/Dec). "Fuzzy Binning" is a discretization technique where continuous measurements are rounded into discrete "buckets" (e.g., 0.5° increments) to make them resilient to minor sensor noise.

B. SYSTEM IMPLEMENTATION:
The system identifies the 5 brightest stars in the Field of View (The Pentagon) and calculates all 10 unique distances between them. These distances are rounded to the nearest 0.5°, sorted, and concatenated into a "seed string."

C. RATIONALE:
This serves as our "Physical Multi-Factor Authentication." Because the star geometry is dependent on the satellite's exact position and orientation in space, it cannot be spoofed by a terrestrial adversary. The "Fuzzy Binning" ensures that even with slight orbital jitter or atmospheric distortion, the Ground Station (predicting the view) and the Satellite (capturing the view) converge on the exact same mathematical seed.
